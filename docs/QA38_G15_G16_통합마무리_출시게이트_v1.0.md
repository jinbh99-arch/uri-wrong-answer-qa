## 1. 문제 분석과 우선순위

| 문제 | 이전 QA의 한계 | 이번 조치 | 추가로 남은 조건 |
|---|---|---|---|
| 가족 로그인 잠금 우회 | 실패 추적 256개가 꽉 차면 가장 오래된 값을 삭제해 잠금 중인 가족도 퇴출 가능 | 활성 잠금 포함 기존 기록을 절대 퇴출하지 않고 새 ID를 429로 차단. 암호화 재시작 검사 | 분산 서버·계정별/IP별 운영용 남용 방어, 침투검사 |

**결정 근거:** 실운영 공급자와 보호자 확인/법적·윤리적 승인이 없는 상황에서 실제 아동 데이터 수집이나 자동 클라우드 배포를 강행하지 않는다. 먼저 기존 QA 구현의 취약 지점과 백업/검증의 누락을 수리하고, 완료 기준을 자동 검사 가능한 데이터로 만든다.

## 2. 개발 변경물

- `scripts/qa-family-gateway.mjs`: 로그인 제한 추적 포화 시 기존 잠금 삭제 금지, 새 가상 ID 등록 한도 100, 응답 보호 헤더, 요청 시간·헤더 수 제한.
- `tests/qa-security-capacity.mjs`: **256개 가상 ID 실패 기록 포화**, 보호받아야 할 기존 잠금 유지, 다른 가족 로그인·원본 유지, 암호화 재시작, 잠금 만료 해제, 외부 출처 차단, 100계정 한계.
- `data/qa38-release-readiness-v0.1.json`: G15 5개·G16 5개 외부 승인 증빙 게이트 등록. 모든 게이트 `BLOCKED`.
- `scripts/qa-release-readiness.mjs`, `tests/qa-release-gates.mjs`: 승인 누락·중복·거짓 승인·실사용자 수 증가·외부 증빙 없는 기술 완료 선언을 검증 실패로 처리.
- `.github/workflows/qa-e2e.yml`: 이번 검증을 전체 CI의 일부로 포함.
- `README.md`: 이번 배치와 이용 금지·미완료 표시 업데이트.

## 3. G15 실제 운영 아키텍처 — 구현 전 수락조건

**계정/권한:** 보호자 인증 제공자의 인증 결과와 보호자-자녀 관계 확인이 필요. 가족별 불변 테넌트 ID와 역할(보호자/아동/운영자)의 최소 권한 경계. 아동 정보는 성인 보호자 인증/동의 없이 서버에 들어가지 않도록 설계. 관리자/고객센터에도 기본적으로 사진 열람권한 부여 금지.

**데이터 동선:** 공개 Pages 격리 QA와 실운영 개인 데이터 전송·저장소를 완전히 분리해야 함. HTTPS + 서버 토큰 검증 + 가족 레벨의 행 접근제어 + 사진 객체 저장소의 서명 URL 만료·접근검사. 클라이언트가 제출한 familyId만으로 서버 권한이 결정되면 안 됨. 저장 시 revision 조건부 갱신, 같은 레코드 충돌은 부모 확인·명시적 병합 경로만 허용. 복원은 무결성 검사 및 원본 보호 절차 필수.

**운영 통제:** 저장 지역·보존 기간·파기·사진 메타데이터·개인정보 처리 위탁처·정보주체 열람·정정·삭제·동의 철회·침해대응 계획 확정. DB PITR/객체 버전, 암호키 교체, 사고 추적(민감 본문·토큰 로깅 금지), 운영 권한 분리·복구훈련·장애 복원 시간 등은 실제 제공자 환경에서 검증 필요.

**인증 공격 방어:** 로그인 남용·가입 폭주·비밀번호 복구 악용·CSRF/XSS/CORS·토큰 탈취·세션 폐기·권한 상승·가족 간 교차접근에 대한 보안 검사. 단일 Node 임시 폴더의 QA 인증 서버는 이 수락기준을 대체하지 못함.

**실기기:** Android/iOS에서 각각 촬영·OCR·재풀이·부모 확인·오프라인 후 복귀·2기기 동시 수정·서버 장애·삭제·복원·사진 바이트 보존·낡은 기록 차단을 검증하고 버전·OS·기기·재현 증거 남김.

G15는 위 조건의 실제 결과가 모두 확인되기 전 **완료·배포 승인 불가**. `issues/20`은 열린 상태 유지.

## 4. G16 실제 교육효과 연구 전제

연구 참여자는 **0명**. 가상 보고서만 있으므로 학습 효과 주장 금지. 실제 연구 개시 전에 법정대리인 동의·관련 윤리 승인·연구 참여 철회, 원문 성취기준 연계 독립 평가도구 전문가 검토, 비교군/할당·교란변수·결측/탈락 처리, 일차/이차 지표·표본 크기 검정력·등록 시점을 사전 확정해야 함. 실제 연구 자료는 공개 GitHub QA 저장소에 절대 업로드하지 않음. 사용자 답안·학교·학년반·사진과 연구 가명 대응키는 별도 접근 제어 환경에서 관리.

기존 `data/qa-study-protocol-v0.1.json`은 **DRAFT_NOT_APPROVED**. 표본수 산식·가상 점수 시뮬레이션은 계획 자료이지 인과적 효과 증거가 아님. 실제 대조/비대조의 한계, 탈락편향·불확실성, 개선이 없는 결과도 그대로 보고. 독립 검토 완료 전 `issues/21` 종료 금지.

## 5. 확인 규칙 및 인계

1. 보안 포화·재시작·계정 상한 + 연구 출범 차단 테스트가 모두 **실행되어 통과**해야 코드 기술 검증으로 기록.
2. 기존 QA25~37 전체 Chromium·수학·사진·백업 회귀검사 유지. PR과 병합 메인에서 확인.
3. 소스-only ZIP의 `scripts/*.mjs` 포함·임시 복원·JS 구문검사·SHA-256 검증; **아동 학습 데이터 백업으로 오인 금지**.
4. QA 자체 문서가 G15 실제 공급자/보호자 인증, 운영 개인정보 승인 또는 G16 실제 학생 실증 완료를 인증할 수 없음.
5. 외부 권한이 없는 상태에서 가능한 독립 작업은 본 저장소의 합성 코드·검증·연구 설계·문서화에 한정한다. 실제 배포·실아동 수집/연구 참여 등록은 별도 승인 및 검증 필요.
