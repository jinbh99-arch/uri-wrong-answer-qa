# A-03 신규 오답 첫 등록 ACK 불명 — 정적 차이 분석 (2026-11-16)

기준: dev 3eac1ec8fbf9a38b75ca317c4088dd9c759ac39b. A-02 기존 재풀이/부모 관찰 8/8 PASS 재실행 금지.

## 신규 차이와 정적 근거
- 실제 앱 index.html의 새 오답 저장 경로는 v20SaveMistakeGuarded 이후 transactionDone=true, readOne('mistakes',id) 및 사진 재읽기/바이트 대조, restoreState, detail 이동으로 이어진다.
- 재읽기 실패 시 '저장 동작은 실행됐으나 ... 중복 등록하지 말고 ... 목록 ... 확인' 안내는 이미 구현돼 있다. 따라서 A-02와 동일한 일반 ACK 불명 경고를 새 결함이라고 주장하지 않는다.
- 그러나 신규 등록은 기존 기록 재풀이/관찰과 달리 **최초 id가 사용자에게 아직 노출되지 않는 경로**다. transactionDone=true 후 재읽기 실패 시 폼에 머무르고, 다음 submit 시 신규 id를 다시 생성하는지 확인이 필요하다. 이 경우 사용자가 목록 확인 없이 재클릭하면 동일 문제 두 건이 생길 수 있다. 이는 **가설**이며 동적 검증 전 제품 결함으로 확정하지 않는다.
- 확인된 UI: #save-btn, #form-error, #v13-save-state, #v09-save-confirm. 재읽기 실패 안내 자체는 기존 구현이므로 신규 UI 보완은 중복 저장 재현 시에만 수행한다.

## A-03 신규 검증 수용 조건 (합성 데이터 전용)
1. 실제 dev 앱, 빈 격리 IndexedDB, 가상 문제 문장 및 선택적 1px PNG를 준비한다. 초기 원장 0건을 확인한다.
2. 최초 등록 쓰기는 성공시키고, **그 직후 최초 readOne('mistakes',id) 단 한 번만 실패**하도록 주입한다. 실패를 쓰기 전으로 옮기지 않는다.
3. 화면의 저장 불명 안내·버튼 활성·폼 보존·최초 원장 건수와 id를 캡처한다. A-02 재풀이/관찰 테스트는 재사용하지 않는다.
4. 사용자 재클릭을 합성하고 새로고침 뒤 원장을 재읽어 **원장 1건, 동일 사진 바이트, 메모, 기존 시각/ID 불변** 여부를 판정한다. 2건이면 신규 등록 중복 결함이다.
5. 필요할 때만 최초 id/재시도 가드 및 '저장 확인 필요' 상태를 index.html 국소 수정한다. 실패 이후 무조건 '저장 완료'를 표시하지 않는다. 중복 위험 해소 후 320/390px Chromium 화면·스크린샷·원장 JSON 및 신규 회귀를 제출한다.
