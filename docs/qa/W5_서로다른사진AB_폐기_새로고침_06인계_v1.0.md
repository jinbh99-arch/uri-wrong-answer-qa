## 1. 문제점과 직접 확인 근거

[00 최신 실행 지시 #6972320980](https://github.com/jinbh99-arch/uri-homework-manager/issues/82#issuecomment-6972320980) 및 [02 정적 분석 #6972267178](https://github.com/jinbh99-arch/uri-homework-manager/issues/82#issuecomment-6972267178): 이전 W5 [`qa/wrong-w5-discard-upload-reload-20261115`](https://github.com/jinbh99-arch/uri-wrong-answer-qa/blob/qa/wrong-w5-discard-upload-reload-20261115/tests/qa85-w5-discard-upload-reload-chromium.mjs)는 **저장할 원본 사진 A와 폐기할 대체 사진 B에 같은 `PNG` 버퍼**를 사용했다. 저장사진의 바이트가 잘못 바뀌어도 동일 버퍼면 `deepEqual`이 허위 통과할 수 있어 시험 설계상 변별력이 부족했다. 이전 브랜치는 현재 dev보다 **4커밋 앞/6커밋 뒤**이고, 시험 폭은 320px뿐이다. 이전 성공 CI 반복 실행 또는 그 시험의 390 PASS 소급 주장 금지.

**채택한 최소 차분:** 제품 `dev` 고정 `3eac1ec8fbf9a38b75ca317c4088dd9c759ac39b`에서 **새 격리 브랜치** `qa/wrong-w5-distinct-photos-discard-reload-20261118` 생성. 실제 GitHub commit diff는 **신규 테스트·신규 워크플로 2파일만**, 제품 `index.html` Git blob `250aff5b0a46490488b64f7b96a83c940d2d6c71` 및 미리보기 서버 바이트 불변. `safeToRestore:false`; PR #80 Draft·미병합.

## 2. 합성 자료의 변별성 확보

- 원본 A: **4×4 진한 파랑** 실제 PNG, SHA256 `0c74eac51649a3bcbbd9564aa25776d08a300ff7d4193534657bc8bbc6ab4a83`.
- 교체 후보 B: **4×4 주황** 실제 PNG, SHA256 `b7cde7c3340183bf5044c6f58efa9425bcfe1ef541c04bbb5a16081bada20cc1`.
- 소스에서 A/B 두 원본 해시를 각각 상수로 **assert**, `assert.notEqual(A,B)`. B 파일 선택 뒤 브라우저 파일 바이트 자체의 SHA가 **정확히 B**인지, 새 사진 캔버스 픽셀이 **RGBA [239,135,33,255]**인지 별개 확인.
- 기존 저장 A의 IndexedDB `photos` Blob는 이미지 변환/압축 가능하므로 A **입력 PNG 해시와 저장 Blob 해시가 같다고 가정하지 않는다**. 앱이 실제 저장한 Blob의 바이트·사진ID·레코드 원본을 기준선으로 고정하여, 이후 어느 단계에서든 동일해야 한다고 단언한다.
