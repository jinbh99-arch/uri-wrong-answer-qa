## 3. 신규 실브라우저 시험 계약(00 승인 후 실행할 항목)

### 사전조건 — 두 페이지 모두 실제 HTTP 200 확인

- `startWrongQa66Preview({devSha: DEV, ...auth})`를 재사용하고, `browser.newContext({viewport:{width:320|390, height:800|850}, httpCredentials: auth})`와 **합성** 오답 1건/가상 PNG만 사용한다. 외부 HTTP 요청은 기존과 같이 송신 전 차단.
- `entryUrl = preview.url + 'index.html'` 또는 명시적으로 `new URL('/index.html', preview.url).href`, `baseUrl=preview.url`. `await page.goto(entryUrl)` **응답.status===200** 및 실제 앱 요소(`#nav-add`, `#page-home`) 확인. `await page.goto(baseUrl)` 역시 **200** 확인. 서버 `if(query)return done(403,...)`는 변경하지 않고 `?a1822=entry`가 아닌 **실제 앱 화면 2개**를 쓴다.
- 첫 페이지와 현재 페이지가 모두 앱이므로 같은 출처·동일 IndexedDB를 공유하지만 **새 문서**다. 두 문서가 동일한 앱 코드를 로드했음을 실행 SHA/Git blob으로 확인. 사용자 작업(파일 선택/메모 입력/저장 버튼)은 실제 Chromium에서 수행.

### 실패→머무르기→정상 저장→다른 앱 URL 복귀

1. **오답1 생성 및 원장기준선:** 새 가상 사진/오답을 1회 저장하고 독립 `mistakes/photos` 재조회, 1건/사진 바이트·내용 해시를 캡처한다. 첫 페이지에서 생성하는 것은 아님.
2. **한 번만 저장 실패 주입:** `IDBDatabase.prototype.transaction`의 `mistakes` readwrite 최초 호출만 synthetic `AbortError`로 실패시키고, 메모 `#check-memo`와 선택된 관찰 상태가 기존 DOM에 남았는지 확인. 다른 저장·가족/실사진 쓰기 금지.
3. **이탈 전 시퀀스 캡처:** `page.url()`, `location.href`, `history.length`, `history.state`, `#check-memo`의 정확한 합성 문자열, 상세 화면 visible, 기록/사진 해시, 타임스탬프를 **JSON event timeline**에 담는다. 이전 목적지 URL과 **현재 base URL을 별도 필드**로 기록.
4. **브라우저 뒤로가기(구현상 `history.back()`)** 후 native `beforeunload` 이벤트/대화상자를 수집하고 `dialog.dismiss()`로 ‘머무르기’. 이 시점 **page.url===baseUrl**, 메모 값 정확 보존, 상세 화면 보임, `history.state` 전후·기록/사진 해시 및 외부 요청/JS 오류 0을 검사. 실제 모바일 시스템 뒤로가기와 동일하다는 주장 금지.
5. **정상 재시도 저장:** 최초 트랜잭션 주입 복원 확인, `#check-save` 재시도 1회, `checkHistory.length===1` 및 사진/기존 오답 바이트 불변. 저장 성공 뒤 `#check-memo`가 비워져 경고 해제되는지 확인.
6. **저장 후 뒤로가기:** 재차 `history.back()` 호출 시 native 이탈 경고 **추가 없음**, `page.url===entryUrl`, 앱 제목과 `#nav-add`/앱 내비게이션 요소 존재, 브라우저 HTTP 응답 **정상 앱 경로** 확인. BFCache 복원으로 네트워크 GET이 새로 발생하지 않을 수 있으므로, **최초 GET 200 기록 + 도착 UI/URL + 선택적 `page.reload()` 응답 200**을 별도로 검증하고 '뒤로가기 때 HTTP GET 200 발생'이라고 표현하지 않는다.
7. **복귀 후 재읽기:** 재진입/새로고침 후 IndexedDB 오답 1건, 관찰 이력 정확히 1건, 사진 바이트 불변, 합성 메모가 저장되었는지 확인. 이전 `?a1822=entry` 403 페이지가 더 이상 목적지가 아님을 단언.
8. **매 폭 4 PNG 이상과 상세 JSON:** 실패 직전/머무른 직후/저장 직후/정상 앱 복귀 직후 각각 PNG, event timeline(JSON), 요청별 URL·상태·타임스탬프, SHA256/ Git blob을 보존한다. **320/390 두 폭 각각 독립 결과**. 정상 앱의 재열람 후 세부 상태를 추가 PNG로 저장할 수 있다.

## 4. 격리·원복/중복 방지

- 기존 A18-22 **RED 44137806914 / GREEN 44138438965 재실행 금지**. 이미 통과한 320/390 메모 보호 경로 전체를 다시 시험해 '새 기능 PASS'로 계산하지 말고, **신규 200 목적지/URL·history.state/앱 재진입 경계**를 새 검증으로 구분한다.
- 실제 수정 필요 여부는 테스트 실행 결과로만 판단. 저장 보호 코드는 현재 QA에 6줄 국소 `beforeunload` 가드로 존재하나 **제품 dev엔 없음**; 이를 제품에 복사하거나 다른 QA 브랜치를 변경하지 않는다.
- 검증용 새 브랜치는 안전한 원본 QA 실행 SHA에서 포크하며 코드는 **전용 신규 테스트+workflow**가 우선. 변경 전후 `git diff`와 모든 blob 해시, 파일별 역패치/기준 SHA를 제출. 실패해도 기존 결과를 덮어쓰지 않는다.
- 06 독립 판정은 새 실행 원시 ZIP·PNG·JSON 직접 대조 뒤 PASS/FAIL/N/T. 실기기, 실제 가족/사진/OCR/Access/서버 원장/복원·삭제/광고/배포는 **N/T 및 승인 범위 밖**.
