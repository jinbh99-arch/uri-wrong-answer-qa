# A18-12 내부 직접 호출 우회 경계 — 신규 정적 판정 (2026-11-17)

기준: 02 제품 dev `3eac1ec8fbf9a38b75ca317c4088dd9c759ac39b` (이번 회차 원격 HEAD 재확인 전 기준값). QA는 A18-11 CI 성공 브랜치 `qa/wrong-a18-11-real-restore-guard-ui-20261117-1315`에서 분기. 제품 dev/PR80 변경 없음.

## 원인·증거
- A18-11 생성기 `qa/a18_10_restore_guard.py`의 `FINAL_SCRIPT`는 버튼 `onclick`, 파일 `onchange`, DOM 캡처 이벤트를 차단한다. 이는 UI 경계의 방어이며 **프로그램 내부 복원 함수의 공통 진입 게이트가 아니다**.
- 같은 생성기 `GUARDED_HANDLER`는 첫 번째 `$('import-file').onchange`만 즉시 반환하도록 치환한다. A18-11 보고서가 명시한 후속 `v07ImportBase`·`v18OriginalRestore` 래퍼의 **내부 직접 호출 가능성은 여전히 미검증**이다. 최종 DOM 핸들러를 다시 할당하는 방식은 이전에 캡처된 함수 참조, 직접 함수 호출, 별도 복원 API를 무효화하지 않는다.
- 따라서 UI 320/390 PASS는 프로그램 내부 경로의 복원 실행 불가를 증명하지 않는다. **직접 호출을 통한 데이터 변경 성공이 관측되었다는 의미도 아니다.** 원자적 revision/CAS 및 실제 복원 안전성 미검증.

## 선택한 해결 방향
복원 허용 판단을 버튼·이벤트가 아닌 실제 데이터 쓰기 직전의 **공통 비동기 실행 게이트**에 두어야 한다. A격리에서만 `safeToRestore === false`일 때 기존 자료 변경을 시작하지 않고 경고를 반환하도록 구성하고, 내부 직접 호출·파일 입력·버튼 모두 같은 게이트를 경유하는지 확인한다. 단순 `onclick` 덮어쓰기나 `disabled`만 추가하는 방안은 기각한다.

## 다음 실행 가능 단위 A18-13
1. 실제 `index.html`의 `v07ImportBase`, `v18OriginalRestore` 정의와 호출부 **관련 줄만** 추출하여 최종 IndexedDB 쓰기 함수·다른 직접 진입점의 도달성 지도를 작성.
2. 실제 쓰기 진입점이 하나로 확인되면 그 지점에 **QA 전용 최소 fail-closed 게이트**를 적용. 여러 경로라면 각각의 쓰기 직전에서 차단; 기존 데이터 쓰기 동작 자체는 실행하지 않음.
3. 합성 가상 사진 Blob·오답·부모 이력·pending 원장 스냅샷을 비교하고, 직접 호출 실패 주입 + 320/390 Chromium 신규 회귀 + 원본 전체 바이트 역패치. 실패 시 수정 후 해당 신규 사례만 재시험.
4. CI 아티팩트와 정확한 QA SHA를 남긴 후 00 판단을 기다린다. 원자 CAS, 실복원, 실제 가족 데이터, 운영/배포는 계속 BLOCK.
