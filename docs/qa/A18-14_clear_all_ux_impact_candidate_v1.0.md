# A18-14 전체 삭제 UX 부작용 — 격리 패치 후보

기준: A18-13 QA 실제 코어 게이트 PASS (CI 44029740277), 제품 dev 3eac1ec8fbf9a38b75ca317c4088dd9c759ac39b (현재 원격 재확인 미실시).

## 신규 차이
A18-13에서 `v22RestoreOnlyIfUnchanged`가 주 DB 전체 교체를 차단하므로 `clear-all` → `v213ClearOnlyIfUnchanged`도 차단된다. 현재 UI는 먼저 전체 삭제 확인을 요청하고, 사용자가 확인하면 마지막에 일반적인 '전체 삭제에 실패했습니다' 안내만 한다. 자료는 보존되지만 삭제 가능 여부를 잘못 기대하게 만드는 UX 결함이다.

## 대안 비교 및 선택
1. 코어 차단 예외로 삭제 허용: 데이터 파괴 경계 위반이므로 기각.
2. UI 확인 이전에 차단 상태를 안내: 자료 보존·오인 방지에 적합하여 선택.
3. 버튼 완전 제거: 복구 정책이 확정되지 않은 상태에서 화면 구조 변경이 커서 보류.

`qa/a18_14_clear_ux.py`는 실제 A18-13 QA `index.html`의 `clear-all` 핸들러 한 지점만 변경하는 적용·역적용 생성기다. A18-13 코어 게이트는 그대로 두고, 확인창 전 '전체 삭제는 복원 안전성 검증 전까지 보류됩니다. 기록과 사진은 그대로 유지됩니다.'를 표시한다. 유일 앵커·중복 적용 거부·원본 역복원 바이트 동일성 assertion 포함.

## 검증 판정
코드 후보 등록 및 A18-13 원본의 관련 구간 정적 확인만 수행. **생성기 실제 실행, Chromium 320/390, PNG, IndexedDB 원본 불변 신규 회귀는 N/T.** 따라서 기능 PASS나 제품 적용을 주장하지 않는다. 다음은 격리 CI에서 clear-all 클릭→확인창 미노출·안내 표시·사진/오답/부모이력/pending 불변·코어 직접 호출 차단 유지·역패치 확인. 기존 A18-13 12/12 PASS 재실행 금지. 프로브는 QA 전용이며 제품 이식 시 제거.
