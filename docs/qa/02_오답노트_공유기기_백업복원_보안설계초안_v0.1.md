## 2. 방어 목표·신뢰 경계

위협 주체: (T1) 공유기기에서 같은 브라우저 프로필을 쓰는 다른 사람, (T2) 다운로드 폴더나 클라우드 동기화를 읽는 사람, (T3) 백업 파일을 변경/훼손하는 사람, (T4) 가족 B가 가족 A의 ID/백업을 제시하는 경우, (T5) 같은 origin에 실행되는 위험한/제3자 스크립트, (T6) 전원 종료·브라우저 종료·저장소 부족·중복 복원.

필수 목표:
1. 가족 A의 *평문* 기록·사진·메모는 가족 B에게 노출되지 않아야 하며, 권한 판단은 단순 UI 토글·URL 경로·가족 ID 문자열만으로 하지 않는다.
2. 기기를 함께 쓰는 경우, **백업 취소와 기록 삭제는 다른 동작**임을 명확히 하고, '잠금'과 '삭제'의 의미·보호 범위를 별도 정의한다. 승인 없는 자동 삭제/보존기간 변경 금지.
3. 백업은 사진을 포함한 **전체 페이로드**를 인증된 암호화로 보호하고, 비밀키가 없거나 변조되면 복원 전 단계에서 실패하도록 한다. 암호화 불능 시 평문으로 자동 대체하지 않는다.
4. 복원은 입력 검증·가족권한 확인·충돌 사전검사 후, 기록·사진의 **동일 IndexedDB readwrite 트랜잭션**에서 원자적으로 반영; 중단/오류 시 대상 원장 불변. 기존 자료 교체·병합은 별도 사용자 확인 및 보존/삭제 정책 승인 필요.
5. 모든 성공/실패 메시지는 실제 커밋/다운로드 결과에만 근거한다. 해시만 있고 인증되지 않은 파일은 '신뢰할 수 있는 복원'으로 표현하지 않는다.

## 3. 대안 비교와 권고 (아직 정책 미확정)

| 대안 | 공유기기·가족 경계 | 평문 백업 위험 | 장점 | 한계·승인 여부 |
|---|---|---|---|---|
| A. 현행 동일-origin·브라우저 평문 보관 + 경고 | ❌ 동일 브라우저 재진입 노출 | ❌ 그대로 노출 | 현행 데이터 무변경·빠른 QA | **출시 수용 불가** |

**권고:** 비운영 설계 검토는 B의 암호화 파일 형식과 실패 원자성으로 구체화하되, **운영 출시 전 실제 가족별 Auth/인가·공유기기 접근통제와 별도 출처/스크립트 신뢰경계를 다루는 C 결정을 선행**한다. 암호화 백업만 적용해도 현재 동일 브라우저의 평문 IndexedDB 노출 문제는 해결되지 않는다.

## 4. 비운영 암호화 백업 포맷 제안 (초안)

- 명시적 형식 판별자, `formatVersion`, `schemaVersion`, `kdf={name,parameters,salt}`, `cipher={name:'AES-256-GCM',nonce}`, `ciphertext`; 바깥 메타는 최소화하며 **학생 이름·답안·사진·부모 메모를 평문 메타에 포함하지 않음**.
- 전체 본문(개념·오답·사진 바이트·아이 설명·보호자 메모·복습 계획 등)을 하나의 인증된 페이로드로 묶고, **버전·앱 식별자·서명된/인가된 가족 불변 ID**를 AAD로 결합. 메타데이터 바꿔치기나 잘못된 가족으로 가져오기 실패 처리.
- 대칭 암호는 Web Crypto의 AES-GCM(256bit), 암호화 시마다 고품질 난수 **새 nonce 96bit**; 같은 키·nonce 재사용 금지. KDF salt도 백업마다 별도 생성. KDF 선택/비용은 실기기 성능·최신 암호 권고·보안검토 후 확정(현행 합성 PBKDF2 120000 반복은 **운영 안전성 보증이 아님**).
- 내보내기·가져오기는 비밀 유출을 막도록 비밀번호/키를 기록·분석·URL·로그·파일명에 담지 않고, 잠금 상태에서 비밀키 수명과 메모리/세션 처리 정책을 정의. 키 유실과 백업 복원 불가 안내 필요.
- 평문 JSON 내보내기는 기존 데이터 손상 회피를 위해 이번 QA에서 **기능 변경/삭제하지 않음**. 운영에서 폐지·기본설정 변경 시 데이터 이전 및 사용자 고지/승인 필요.
- 검사값(SHA-256)·CRC32만으로는 가족권한, 백업 발신자 진위, 기밀성을 보장하지 못한다. **AES-GCM 인증 실패 = 가져오기 중단 + 대상 원장 0건 변경**.

## 5. 복원·데이터 보존 절차 및 부정 테스트 수용 기준

1. **쓰기 전 검사:** 파일 크기·형식 버전·사진 타입/바이트·개수/길이·필드 제약·가족 인증과 권한·GCM 인증·전체 레코드 일관성을 검사하고, 실패 시 기존 기록·사진·설정 변경 **0**.
2. **중복/충돌:** 같은 기록 ID 충돌과 다른 가족 ID 혼입은 원칙적으로 거부. 일부 자료만 반영·의도치 않은 덮어쓰기 **0**. 병합/교체 정책은 승인 전 동작 고정.
3. **원자성:** 합성 IndexedDB 예비 복원 트랜잭션을 강제 abort·quota 실패·브라우저 중단/재시작·중복 제출·중간 사진 오류로 시험, 기록 및 사진 snapshot 바이트 등가성 검사.
4. **명시적 허용:** 데이터 손실 가능/덮어쓰기 범위가 사용자에게 설명되고 명시적으로 동의한 경우에만 실제 commit. 완료 메시지는 commit 확인 후 표시. 취소·Escape·암호 오류는 다운로드/쓰기 **0**.
5. **키/인가 경계:** 잘못된 암호, 잘못된 가족 키, 바뀐 family ID, nonce·salt·AAD·ciphertext 변조, 낡은 형식·부분 파일·대용량 압축 폭탄 거부. 실제 인증·서버 권한 검사 없음 상태는 *합성 실험에 한정*.
6. **접근성:** 320·390px CSS200에서 긴 경고를 숨기지 않고 세로 스크롤, 초점 표시, Tab/ShiftTab/취소/보존 안내, 스크린리더 실기기 별도 검증. 새 백업 UX는 기존 63개 회귀 삭제/완화 없이 차분 검증.
