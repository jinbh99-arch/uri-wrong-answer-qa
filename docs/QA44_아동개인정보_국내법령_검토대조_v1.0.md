## 핵심 법령상 의무와 코드 대응

| 공식 근거 | 요구되는 기본 방향 | 현재 구현·검토 상태 |
|---|---|---|
| 제22조의2 제1항 | **만 14세 미만 아동의 개인정보 처리를 위해 법상 동의를 받아야 하는 경우**, 법정대리인 동의 및 그 동의 여부의 확인 | Supabase SQL에 `verified_at`과 `consent_verified_at` 분리·미확인 접근 차단. **실제 법정대리인 확인 방법·동의 증거 수집 전무**, 구현 완결 아님 |
| 제22조의2 제3항 | 아동에게 개인정보 처리 고지를 할 때 이해하기 쉬운 방식·언어 사용 | 별도 아동용 쉬운 안내문과 UI 검수 필요. 실제 고지 미시행 |
| 제38조 제2항 | 만 14세 미만 아동의 법정대리인에게 열람·정정·삭제 등 권리행사 가능 | 실제 사용자 권리신청 접수·심사·이행·증명 절차 미구현. 서버 RLS만으로 충분하지 않음 |
| 제38조 제4항 등 | 구체적인 권리행사 방법 공개, 어렵지 않은 절차 | 공개 문의채널·운영자·법적 처리기한 확정 필요. 초안 수준 |
| 기타 적용 조항 검토 | 수집 근거·최소수집·처리위탁·국외 이전·암호화·보관/파기·침해대응 등 | 사업 모델/서비스 위치/사용자/서버 국가/운영위탁 업체 미확정. 법적 검토 필요 |

**법 조문을 과도하게 단순화하지 않는다.** 모든 개인정보 처리에 일률적으로 '동의만'이 유일한 법적 근거라고 단정할 수 없지만, 아동 개인정보에 동의를 근거로 수집하는 경우 법정대리인 동의·확인 요건을 충족해야 한다.

## 운영 전 개인정보 자료 목록 (현재 미승인)

1. 서비스 주체·연락처·개인정보 관련 책임자, 수집 항목/필수·선택 및 처리 목적, 법적 근거.
2. 실제 클라우드 저장 국가/지역, Supabase/Resend/Google의 위탁·제3자 제공·국외 이전 요건, 발신 이메일과 로그인 식별자 전송 경로.
3. 학생 자료(닉네임·학년·오답 텍스트·재풀이·사진) 및 선택 OCR의 외부 서비스 제공 범위. 사진에는 학교·이름·학급·위치 등이 포함될 수 있음.
4. 동의 거부·철회, 열람·정정·삭제, 탈퇴, 백업 파기/복원 시 삭제한 정보가 다시 살아나지 않게 하는 기술·절차.
5. 해킹·유출·사고 통지, 최소권한, 관리자 계정 보안, 로그 본문/토큰/사진 미노출, 아동친화적 고지.
6. 실제 아동 정보 수집 전에 보호자 동의 검증수단의 적법성, 동의 증빙과 보존정책, 외부 법률/개인정보 전문가 최종 검토.

## 현재의 기술 대응과 한계

- **기술 대응:** 비공개 가족 DB/RLS, 실제 서버 인증 토큰 사용 예상, 법정대리인 관계+동의 미검증 계정 격리, 가입만으로 가족 데이터 접근 금지, 1MiB 사진 파일 규격, DB CAS 및 원본 사진 보존 검사, Google·이메일 로그인 SDK 호출 준비.
- **아직 구현하지 못한 필수 실운영 절차:** 법정대리인 실제 신원·관계 확인, 동의 수집과 입증, 유효한 개인정보 정책 게시, 수집·보관·삭제·권리행사 업무, 사고 대응, 국외 전송 및 위탁의 적법성 검토, 클라우드 공급자 실제 설정 검증.
- **금지:** 실아동 자료 업로드, 실제 보호자 가입/초대·동의 수집, 법률·보안 '승인 완료' 표시 및 학습 효과 입증 주장.

이 문서는 기술 설계의 법령 대조표이지 법적 적합성 인증서가 아니다. 실제 서비스 출시 전 최종 책임은 실제 개인정보처리자에게 있다.
