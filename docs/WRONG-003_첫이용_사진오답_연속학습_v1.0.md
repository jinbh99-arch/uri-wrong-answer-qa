# WRONG-003 · 첫 이용·사진만 있는 오답의 동일 기록 연속 학습 v1.0
- 작업일: 2026-11-09
- 기반: WRONG-002 PR #45 (`feature/wrong002-connected-study-journey`)
- 기존 저장소: `jinbh99-arch/uri-wrong-answer-qa`
- 허용 범위: `index.html` 기존 앱 UX/인덱스DB 안전 수정 + 합성 Chromium 테스트, 외부 운영 배포 없음.

## 원인 및 재사용한 기존 기능
- 이미 구현: 사진만 저장, v11 사진 미정리 대기열, v13 이전 사진 편집 미리보기, QA10 일반 재풀이, v05 부모 복습 계획, v06 복습 후 관찰, v227 부모 활동 보고서.
- 미완성 UX: 처음 빈 목록에서 문자만으로도 시작할 수 있다는 경로가 충분히 드러나지 않음. 사진만 저장한 뒤 이후 글자를 보완하려면 기존 안내가 여러 구역에 분산돼 있음.
- 데이터 위험: `hasPhoto=true`인 기존 레코드에 해당 사진 Blob이 없거나 읽을 수 없는 상태에서, 텍스트 변경이 먼저 저장된 후에야 사진 부재를 확인할 수 있었음.

## 구현
1. 홈 첫 방문 0건이면 기존 사진 등록 CTA 옆에 **사진 없이 글자 직접 입력** 경로 표시. 등록 후 자동 숨김.
2. 오답 목록이 완전히 빈 경우 별도 직접 입력 CTA 추가. 검색 결과가 0건이어도 저장된 기록이 있으면 첫 이용자로 잘못 안내하지 않음.
3. 사진만 등록한 기존 오답 상세에 **사진 내용 확인·보완** 버튼 배치. 기존 ID를 편집 화면으로 전달.
4. 편집 화면에 기존 v13 저장 사진 미리보기로 이동, 문제 글자 직접 입력으로 이동하는 가이드 추가. 새 사진을 선택하지 않아도 기존 Blob 유지.
5. `hasPhoto=true` 레코드 편집에서 사진을 유지하는 경우 **저장 전 Blob 존재/가독성 확인**. 없으면 메타데이터 수정 자체를 중단. 성공 후 사진 바이트 동일성을 재확인.
6. 모든 학습 연결은 WRONG-002에서 이미 만든 같은 ID의 다시 풀기, 부모 계획, 관찰, 보고서를 사용. 데이터 스키마/사진 인코딩/권한 규칙은 그대로 유지.
7. 아이 보기 모드에서 부모 전용 신규 버튼 숨김. UI 모드는 서버 접근 통제 아님.

## 검증 범위
`tests/wrong003-first-use-photo-flow.mjs`은 320px·390px 실제 Chromium에서 다음을 **합성 1픽셀 PNG**와 가상 오답으로만 실행:
- 0건 홈/목록에서 직접 입력 경로
- 사진만 등록하여 같은 IndexedDB에 사진 Blob 저장, 다른 오답 원본 분리
- 사진 있는 상태에서 아이 모드와 부모 모드 버튼 표시 구분
- 기존 사진 확인→글자·개념 보완→동일 ID 유지 및 사진 byte-for-byte 일치
- 아이 재풀이→부모 일정→복습 관찰→보고서→새로고침 후 데이터 완전 대조
- 가상 사진 Blob만 삭제한 손상 시나리오에서 수정 금지 및 기존 메타데이터 불변
- 브라우저 오류 및 320px·390px 수평 오버플로 검사
