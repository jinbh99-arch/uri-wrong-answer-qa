# QA43 · 2단계 백업·장애복구·데이터 삭제 훈련 v1.0

**실행 범위:** 임시 PostgreSQL 16, 합성 오답/사진, 임시 AES-GCM 복구 파일. 실제 자녀 자료·클라우드·운영 데이터 미사용.

## 수행 가능한 자동 훈련
- `scripts/qa43-recovery-envelope.mjs`: 합성 백업의 무결성을 재검사한 뒤 가족 ID·개정번호를 AAD로 지정해 AES-256-GCM 암호화. 틀린 키·다른 가족·다른 개정·손상 시 복원 거부.
- `tests/qa43-postgres-recovery.mjs`: 두 가족별 분리, 0600 권한 임시 복구 파일, 암호문에 평문 사진/오답 없음, 사진 해시/내용 원본 동일, 임시 DB snapshot 행 사고 손실→승인 보호자 권한 유지 상태에서 복원, DB 연결 재시작 뒤 조회, 저장 해시 훼손 차단, 동시 CAS 충돌, 다른 가족 삭제 cascade, 권한 철회 후 접근 거부를 검사.
- 기존 QA26~42: JWT 위조/만료, 로그인 잠금/재시작, 가족별 권한, 백업·복원 확인, 네트워크 응답 유실, 256회 학습기록까지 자동 회귀검사 유지.

## 운영 적용 전 반드시 추가할 검증
1. 실제 운영 DB의 관리형 스냅샷·PITR·WAL/오브젝트 버전 저장 정책과 **RPO/RTO 수치**를 서비스 책임자가 결정해야 한다. 운영 복구를 성공했다고 기록하지 않는다.
2. 데이터베이스와 사진 객체 저장소를 **동일한 논리 시점**에 복구할 수 있는지 확인. 일부 사진 누락·키 교체·만료된 접근 URL·권한 취소·개정 충돌을 실환경에서 재현.
3. 장애 복구와 개인정보 삭제 요청을 **절대 혼동하지 말 것**. 사용자가 의도적으로 삭제한 가족의 정보는 옛 백업을 통해 자동 부활시키지 않는다. 삭제 지시·파기 시한·보존 법적 근거·백업 보존정책·복구 시 삭제 재적용용 tombstone 설계는 미승인.
4. 복구 시 원본을 덮어쓰기 전 읽기 전용 격리환경에서 해시 검증 및 최소 권한 재승인. 실제 복원 최종 승인·감사 추적·실사용자 통지는 운영 절차가 정한 바에 따라 수행.
5. 비밀키 보관·회전·유실 및 사진 별도 보관·지역·재난복구 시설은 아직 공급자 미선정. QA43 시험키는 테스트 종료 시 폐기하며 절대 실제 아이 자료에 적용하지 않는다.

**미완료:** 실운영 백업 복원/PITR, 사진 스토리지 및 삭제·철회 처리의 법적 승인. QA 합성 시험 통과와 운영 복구 검증을 구분.
