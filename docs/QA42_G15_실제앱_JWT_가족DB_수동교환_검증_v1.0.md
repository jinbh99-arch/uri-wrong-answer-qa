# QA42 — 오답노트 실제 설정 화면 ↔ 서명 JWT ↔ PostgreSQL 가족 기록 연결

**2026-11-08 / 합성 데이터·127.0.0.1 전용 / 실서비스 사용 금지**

## 기존 단절과 통합 해결

QA39는 가족별 PostgreSQL RLS와 충돌 방지, QA40은 RSA 서명 JWT·보호자 권한, QA41은 HTTP API까지 구현했지만, **오답노트 실제 설정 화면은 오래된 로컬 가상 비밀번호 서버만 수동 연결**되어 있었다. 즉, API와 실제 UI가 분리되어 사용성·복원 통합 검증에 빈틈이 있었다.

**이번 QA42에서는** `scripts/qa42-app-http-bridge.mjs`가 실제 오답노트 설정 화면에 시험용 카드를 추가한다. 이 모듈은 오직 `http://127.0.0.1:4173`에서만 동적으로 불러오며 공개 Pages·Netlify에서는 표시되지 않는다. 입력된 JWT는 브라우저 메모리에만 유지하고 입력창을 즉시 비우며, `localStorage`/IndexedDB에 JWT를 저장하지 않는다.

| 사용자 동작 | 실제 수행 및 안전조건 |
|---|---|
| 가상 서명 JWT 입력·연결 | 서명·Issuer·Audience·Expiry 검증 → 서버 DB 보호자 승인된 가족 목록만 표시 → revision 읽기 |
| 오답·사진 보내기 | 가상 자료 확인 체크 필수 → 서버 revision 선조회 → 기존 앱 완전 백업/사진/무결성/복원 호환 검사 → JSON 파일 백업 요청 → 서버 `If-Match` 원자 갱신 |
| 서버 기록 가져오기 | 서버 서명 JWT·보호자 RLS 확인 → 기존 앱의 손실 방지 복원 검사·임시 복원 후 **사용자 확인창**을 거쳐야 원본 교체 |
| 연결 끊김·PUT 응답 유실 | 자동 재전송 없음. 추가 업로드 전 원격 최신 revision 검사. 오답·사진을 임의 삭제/동기화하지 않음 |
| 보호자 권한 철회 | 404/401로 요청 차단 → 가상 JWT 메모리 삭제·버튼 비활성. 오답·사진 로컬 DB는 보존 |

## 실제 브라우저·DB 검증

`tests/qa42-native-app-http.mjs`에서 합성 RSA JWKS, PostgreSQL 16 가상 가족 2곳, 분리된 Chromium 프로필 3개(390/320px)를 동시에 사용한다.

1. 사용자 A/B가 같은 가상 가족, 사용자 C는 다른 가족 JWT로 연결되는지 검사.
2. 실제 앱에서 A가 가상 사진 오답 저장 → 백업·파일 생성 → 서명 JWT HTTP API→Postgres revision 1 저장.
3. B가 서버 데이터를 읽어도 기존 로컬 원본은 **복원 확인창 승인 전에는 변경되지 않음** 확인. 승인 후 사진 바이트 포함 복원.
4. B가 두 번째 오답을 추가하고 서버 `PUT`은 성공했으나 응답만 유실 → 자동 재시도 없음, 재전송도 revision 불일치로 차단.
5. A의 오래된 revision과 네트워크 단절 사전검사에서 새 원본 JSON 다운로드 없이 중단.
6. B 보호자 권한을 DB에서 철회한 뒤, JWT가 여전히 유효해도 앱 전송·조회 차단, 인증 메모리 비움, 로컬 원본 불변.
7. 정확한 루프백 출처가 아닌 `localhost`와 공개 사이트에서는 QA42 카드를 만들지 않음.

## 외부 승인·실서비스 잔여 과제

이 작업은 **가상 JWT를 입력하는 합성 QA 인터페이스**다. 실제 공급자 인증 버튼이나 법정대리인 확인 기능, 실운영 환경의 HTTPS·비밀관리·Postgres 운영 백업/감사·사진 객체저장·데이터 삭제/철회, 실제 스마트폰 2대와 아동 사진의 법적 처리 동의는 **구현/검증되지 않았다**.

또한 원본 앱의 백업 파일은 **암호화되지 않은 오답·사진 데이터**이므로 합성자료 환경에서도 취급에 주의해야 한다. 자동 동기화는 구현하지 않았고 수동 교환에만 해당한다. 실제 아동 정보·가족 계정은 절대 입력하지 않는다.

교육 효과 G16은 여전히 실학생 0명, 윤리/법정대리인 동의·독립 교육 평가 검증 미완료이다.
