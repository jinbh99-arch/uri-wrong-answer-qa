# QA41 — 합성 JWT·가족별 PostgreSQL HTTP API 통합검증 및 출시 경계 v1.0

**2026-11-08 · 공개 합성 QA 저장소 전용 · 실제 운영 API 아님**

## 개선 배경과 선택

QA39에서는 **실제 PostgreSQL 16의 가족별 RLS·동시 쓰기(CAS)** 를 검사했고, QA40에서는 **합성 RSA 서명 JWT와 DB 권한 연동**을 확인했다. 하지만 여전히 HTTP 요청의 인증 헤더, 교차 출처 접근, 요청 크기, 조건부 저장, 에러 응답, 브라우저 통합 전송 계층은 별도로 구현되지 않았다. 이번에는 이 경계를 하나의 **루프백 전용 HTTP API**로 연결했다.

### 신규 산출물

- `scripts/qa41-signed-family-http.mjs`: `QA41_LOOPBACK_ONLY=1`과 QA39·QA40 별도 시험 설정이 없으면 실행 거부. 127.0.0.1의 운영체제 임시 포트에만 연결하며 외부 주소 바인딩 없음.
- `GET /qa41/families`: 서버가 실제 서명·발급자·API 대상·만료를 검증한 JWT와 RLS가 함께 허용하는 가족 식별자 목록만 제공.
- `GET /qa41/families/:familyUuid/snapshot`: 허용된 보호자만 기존 앱 백업/사진/오답 자료와 `ETag: "revision"` 조회.
- `PUT /qa41/families/:familyUuid/snapshot`: 필수 `If-Match: "revision"`, 보호자 확인·가족 권한·백업 SHA-256 검증·원본/사진 보존·SQL 원자 CAS를 모두 적용. 동시 편집 시 오래된 쪽은 409, 무단 접근은 404.
- 허용한 로컬 웹앱 출처(`http://127.0.0.1:4173`)의 CORS 프리플라이트만 통과. 쿠키 자격증명을 활성화하지 않으며 모든 요청에서 명시적 서명 JWT를 요구. 교차 출처·무인증·가족 조회 열거·비지원 메서드·대량 본문·조작 JSON·잘못된 수정조건을 거절. 응답은 `no-store`, `nosniff`, `no-referrer`, CSP.
- `tests/qa41-http-api.mjs`: 실제 CI PostgreSQL과 두 개의 독립 Chromium 화면(390px/320px)에서 서로 다른 가족의 JWT·CORS·공개 API 경계·사진 원본·동시 수정·권한 철회 후 차단을 점검. 브라우저에서는 기존 공개 **check.html의 출처**로 요청하여 CORS 검사를 수행하지만, 오답노트 정식 설정 화면에 이 실험용 API를 연결하는 것은 **아직 진행하지 않음**.

## 운영에 필요한 후속 조건과 한계

| 수락 기준 | QA41 수준 | 실제 남은 사항 |
|---|---|---|
| 인증 | 합성 RSA JWKS 토큰 검증 | 실제 인증 공급자·토큰 발급/폐기·키 회전·재인증 미구현 |
| 가족 권한 | 시험 관리자가 미리 승인한 가상 RLS 행 사용 | 법정대리인 확인·동의·가족 생성/복구/탈퇴 미구현 |
| DB | 로컬 임시 PostgreSQL 16 테넌트 분리·CAS | 실클라우드 비밀관리·TLS·다중 노드·스냅샷/PITR·감사 검증 미실시 |
| HTTP | 루프백 한정 HTTP, 공개 포트 없음 | 실제 HTTPS 리버스프록시·운영 CORS·DoS/침투검사 미구현 |
| 사진/오답 | 합성 Base64 문자열, JSON 최대 1MiB HTTP 입력 | 실제 촬영 사진·사진 객체 저장·메타데이터·무결성/보존/삭제 정책 미확정 |
| 모바일 | Chromium 390/320px 브라우저의 별도 출처 전송 | **물리 스마트폰 2대**·운영 로그인·재연결·사진 실측 미실시 |
| G16 | 실학생 0명, 기존 연구 검토본 유지 | 전문 연구자/윤리/보호자 동의·실제 학생 학습효과 분석 미실시 |

**중요:** 이 서버는 실제 운영용 웹사이트나 클라우드로 노출하면 안 된다. `QA41_LOOPBACK_ONLY=1`은 테스트용 장치이지 생산 보안 인증서가 아니다. CORS는 인증의 대체물이 아니고, DB 세션 변수는 직접 DB 비밀번호 노출 시 인증 수단이 아니다. 브라우저에 DB 접속정보·서명 개인키를 전달하면 안 된다. 운영에서는 허용 출처·요청 제한·JWT 취소/재발급·세션 탈취·개인정보 처리를 서비스 요구사항에 맞게 새로 검증해야 한다.
