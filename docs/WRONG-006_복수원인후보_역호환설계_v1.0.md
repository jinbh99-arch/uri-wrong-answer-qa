# WRONG-006 · 복수 오류 원인 후보 역호환 설계 및 검증 계약 v1.0

## 최초 요구와 기존 구현
- **사용자 원본** `02_오답노트_PRD_v0.2.md`, 명세 4항: *사용자가 선택한 원인 후보와 부모가 확인한 결과를 분리. 여러 원인 후보 가능.* OB-02는 선택적 원인, OB-03은 단정적 진단 표현 금지, OB-05는 실제 재확인 근거 기반. PRD 작성 당시의 '소스 미작성' 문구는 현재 GitHub 제품 상태를 설명하지 않는 과거 문구다.
- 통합총괄 #52 §14 WRONG-006 / R16: 새 배열은 0/1/N 가능, 부모 관찰과 독립, 구형 단일 값·메모/오답 ID/사진·재풀이·백업·가족 교환 무손실. R17의 과목/ID 계약은 **대상 아님**.
- 기존 `index.html`의 `reason`은 `unknown/calculation/reading/concept/other` 중 하나; `memo`는 자유 텍스트. WRONG-005에서는 복수 후보를 `other`와 메모로 표현했으나 **구조화된 복수 선택/검색/복원 검증이 없었다**.

## 역호환 데이터 계약 (선택적 확장, 승인 대기 중인 과목/ID 계약과 무관)

| 필드 | 규칙 | 과거 기록 |
|---|---|---|
| `reason` | **기존 그대로 유지**, 5가지 허용값. 복수 선택일 때 `other`로 집계되는 호환 표시; 1개면 해당 코드, 0개면 `unknown`. **자동 진단/원인 확정 아님** | 기존 저장 값·ID 삭제/변경 금지 |
| `reasonCandidates?` | **선택적** 배열, 중복 없는 `calculation/reading/concept/other` 코드 최대 4개. 0개는 추정 없음, 1개는 단일 추정, 여러 개는 모두 **동등한 미확정 후보**. 별도의 신뢰도/확정값/관찰/우선순위 없음. | 필드가 없으면 읽을 때 기존 단일 `reason`에서 보기를 **계산**하며 자동 저장/일괄 변환 없음 |
| `checkHistory[]`, `followupHistory[]` | 학부모가 복습 후 확인한 이력. 후보가 바뀌어도 삭제·자동 편집되지 않음. | 동일 |
| `conceptId`, `id`, `hasPhoto`, `memo` | 그대로 유지하며 메모는 복수 후보의 설명 등에 활용 가능 | 동일 |

**무손실 보호:** 배열이 존재하면 반드시 정확한 타입/허용 코드/중복/값 수/기존 `reason`과의 대응을 검사한다. 손상된 배열을 빈 배열로 자동 치환하거나 `reason`으로 덮지 않는다. 허용 가능하고 인과 추정이 아닌 구분만 신규 UI에 표시한다. 오래된 앱이 신규 배열을 변경 없이 보관한다고 보장할 수 없으므로 **과거 버전으로 복원/편집해 데이터 보존 여부는 보장하지 않는다**. 정식 공통 데이터 계약/마이그레이션은 별도 승인 필요.
