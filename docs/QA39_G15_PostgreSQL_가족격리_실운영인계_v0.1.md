# QA39 G15 — 가족별 PostgreSQL 저장소 실험과 운영 전 인계 v0.1

**2026-11-08 · 상태: 로컬/CI 실험, 실제 제품 및 보호자 인증 미승인**

## 신규 구현물

- `db/qa39_family_rls.sql`: 검증된 보호자만 해당 가족의 기록을 읽고 바꾸도록 PostgreSQL RLS 활성화·강제. 가족/보호자 지정은 신뢰 가능한 관리자 또는 인증·권한 확인 절차에서만 수행, 앱 역할은 가입/삭제·임의 권한 부여 불가.
- `scripts/qa39-tenant-store.mjs`: 신뢰할 수 있는 외부 인증 결과로 얻은 사용자 식별자를 **서버에서만** 주입하도록 설계된 데이터 접근 모듈. 인증 공급자 연결 전에는 `QA39_REFERENCE_ONLY=1`이 없는 한 실행 거절. 전체 백업 해시 검증 후 원본 JSON 텍스트를 문자열 순서 그대로 보존.
- `tests/qa39-postgres-tenant.mjs`: CI가 임시 PostgreSQL 16을 띄워 분리된 보호자와 가족, 철회·미확인 보호자, 읽기/쓰기 권한, 낡은 버전 충돌, 두 동시 쓰기 중 하나만 성공, 사진 base64 문자열 동일성, SHA-256 변경 거부, 기존 사진 삭제/동일 ID 조용한 교체 거부를 테스트.
- 소스 ZIP·복원 경로에 SQL·저장소 모듈·통합검사를 포함. CI의 데이터베이스는 **합성 임시 데이터만** 사용.

## 중요한 안전·정확성 한계

**DB의 `current_setting('qa39.principal_id')`은 자체 인증 수단이 아닙니다.** DB 계정을 직접 가진 공격자가 세션 변수를 임의로 설정할 수 있습니다. RLS는 **DB를 외부에 노출하지 않고**, 신뢰된 서버가 발급자·서명·대상 등을 검증한 인증 결과로만 이 값을 설정할 때 추가 방어층이 됩니다. 따라서 QA39의 CI 통과만으로 운영용 테넌트 격리 보안을 승인할 수 없습니다.

DB `snapshot_text`에 사용자 기록과 사진 base64가 들어갈 수 있으므로 운영에서는 DB 암호화·접근 제어·백업 정책과 사진 객체 저장 분리를 **별도로 설계·검증**해야 합니다. CI 합성 사진 문자열은 운영 사진과 무관합니다. DB의 저장값 보존 테스트는 스마트폰 실물 사진 처리, 이용자 동의나 운영용 인증의 검증을 대체하지 않습니다.

공개 GitHub Pages는 오답노트 로컬 시험 UI만 제공하며, `scripts/qa39-tenant-store.mjs`는 `index.html`에 연결하지 않았습니다. 실제 어린이 정보나 부모 계정을 입력하지 마세요. **Netlify 운영 서비스·외부 클라우드에는 아무것도 배포하지 않았습니다.**
