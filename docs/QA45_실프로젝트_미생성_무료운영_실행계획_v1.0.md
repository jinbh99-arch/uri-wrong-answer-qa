# QA45 · Supabase 무료 조직 확인 및 프로젝트 생성 금지 실행계획 v1.0

기준: 2026-11-08 / 범위: **프로젝트 미생성·결제 금지·실계정 연결 금지** / 공개 QA 소스만 변경.

## 1. 실제 확인 사실

- 연결된 Supabase 계정의 조직 목록과 세부 조회에서 **`uri-level-test` / plan=`free`, tier=`tier_free`** 확인.
- 사용자 계정의 프로젝트 목록 조회 결과 **0개**. 조직만 존재하며 프로젝트·실제 DB·Auth/Storage는 아직 존재하지 않음.
- 조회는 Supabase 연결의 읽기 전용 메타데이터 작업으로 수행. 프로젝트 생성, 스키마 적용, 인증 공급자 설정, SMTP 키 발급, Storage 버킷 생성, 카드 등록, 유료 플랜 변경, 외부 배포 **모두 미수행**.
- 실계정 운영환경과 단절된 기존 임시 PostgreSQL 16 자동검사(QA44)는 통과했으나 **실제 Supabase에서 성공했다고 간주하지 않음**.

## 2. 사용자가 요청한 5개 작업의 정확한 상태

| 작업 | 프로젝트 없는 상태에서 가능한 일 | 실제 운영 반영 |
|---|---|---|
| ① 무료 프로젝트 생성 준비 | 조직·Free 요금제·프로젝트 0개 확인, 공급자 설정·금지 조건·사전 순서 확정 | **준비 완료 / 프로젝트 생성 0개** |
| ② 가족별 DB·RLS 적용 | `db/qa44_supabase_staging_rls.sql` 정책과 실 PostgreSQL 합성 RLS 검사 및 신규 차단 계약 | **실제 프로젝트가 없어 적용 불가** |
| ③ 구글·이메일 로그인 설정 | `scripts/qa44-supabase-auth-adapter.mjs`와 Google OAuth/이메일 가입·재설정 합성검사 | **실제 발급자·OAuth·SMTP 등록 전 미설정** |
| ④ 사진 저장소 권한 설정 | 비공개 버킷 SQL/경로·1MiB 제한·가족 승인 RLS·차단 테스트 | **실제 Storage 버킷 미생성** |
| ⑤ 합성자료로 실제 서버 보안 시험 | 임시 PostgreSQL·실 Chromium의 합성자료 검증(QA44) | **실서버 자체가 없어 불가** |

`data/qa45-free-no-project-plan.json`에 이 상태와 *외부 승인/실기기/실아동/운영비 0* 게이트를 기록하고, `scripts/qa45-no-project-guard.mjs` / `tests/qa45-no-project-guard.mjs`로 허위 승인·유료 전환·실서버 성공 주장 차단.

## 3. 프로젝트 생성 허용 이후에만 실행할 순서 (현 단계에서는 실행 금지)

1. **명시적 생성 요청**을 받고 `uri-level-test` 개인 조직·Free 요금제·허용되는 저장 지역·프로젝트 이름·DB 관리 역할 검토. 프로젝트가 없다는 이유만으로 생성하지 않는다. 결제·신용카드·Pro/Team/Compute 업그레이드 메뉴는 누르지 않는다.
2. 생성한 후, **실제 Supabase auth/storage 스키마·버전·정책·GRANT 및 공개 API 스키마 설정**을 별도로 읽기·검토. `qa44_supabase_staging_rls.sql`의 `CREATE ROLE` 및 정책 이름/Storage 기존 권한과 충돌 여부를 사전에 점검. SQL은 미리 검증된 분리된 합성 프로젝트에서 시험하고 그 후 적용; 무작정 운영에 붙여넣지 않는다.
3. **Google 로그인:** 실 Google Cloud 소유자가 OAuth Consent Screen(서비스 명칭·허용 계정·콜백 주소 등)과 클라이언트 정보를 발급·승인. 비밀키는 GitHub/채팅/프런트에 입력 금지. 실제 토큰 검증과 로그아웃/권한 철회 시험.
4. **이메일 로그인:** Supabase email provider/confirmation/비밀번호 복구 검증. 기본 발신 서비스는 일반 사용자 운영용으로 불충분하므로 Resend 등 실제 SMTP 후보의 무료 요금제·발신 도메인 소유·SPF/DKIM/관리 키를 확인해야 함. 결제 수단 필수이면 사용자 승인 전 중단. 실제 사용자에게 테스트 메일 발송 전 안전한 테스트 주소로 제한.
5. **가족별 접근:** Google/이메일 계정만으로 아동 개인정보 접근 허용하지 않음. 법정대리인 관계 실제 신원·동의 검증 및 기록·철회·삭제·위탁/국외이전·처리방침이 **승인된 이후**에만 가족 리소스를 공개. `auth.uid()` RLS와 서비스 권한의 '서버에서 확인' 분리, 사진 공개 URL 금지.
6. **합성자료 실서버 테스트:** 신규 무료 DB에서 서로 다른 2인 합성 계정과 임의 사진으로 최초 등록/타가족 접근 거부/읽기·쓰기/충돌/권한 철회/사진 원본 해시/사고 롤백·삭제를 직접 실측. 프로젝트 외부 접근과 정확한 API 권한을 확인한 뒤에만 다음 상태. 모든 로그에서 이메일·토큰·사진 본문 제거. 물리 Android/iOS는 별도 검수.

## 4. 운영 비용·보안·법적 한계

- 목표 금액 0원, **유료 과금 승인 없음**. `scripts/qa44-free-budget.mjs`의 80% 사용량 경고·예상 한도 차단은 **예상 계산용**이며 실제 공급자 과금 중단 기능이라고 오인하면 안 됨. Free 용량·작동 보장은 불가.
- 실제 유저 초대/가입·아동정보 수집은 금지. 개인정보 보호법 제22조의2·제38조 등에 대한 법령 검토 초안만 있으며 운영 책임·법정대리인 동의 검증·제3자 위탁·국외 이전·정보주체 권리행사 등은 별도 법적 검토/승인 필요.
- Supabase 무료 플랜은 운영 등급의 복구·PITR이 검증되지 않았다. 사진·DB의 같은 시점 복구를 제시하기 전 실제 가정의 기록을 저장해서는 안 됨.
- 기존 Netlify 운영 서비스와 기존 GitHub Pages 실제 아동 데이터는 건드리지 않음. 공개 저장소에 service_role 키, 개인 DB 비밀번호, OAuth client secret, 발송 서비스 키 보관 금지.

## 5. 객관적 인수 기준

**현 단계 인수 가능한 것:** Supabase `uri-level-test` 무료 조직 확인, 프로젝트 0개, QA44 코드/SQL/가상 브라우저·임시 PG 검증 유지, QA45 비생성·비과금 계약 CI PASS, GitHub 소스-only 백업·검사 통과.

**현 단계 인수 불가능한 것:** 실제 Supabase DB·RLS 적용, Google OAuth 실로그인, 이메일 전달/Resend 실전송, 비공개 Storage 실버킷, 실서버 보안·복구 실측, 실제 아동 법정대리인 확인 및 동의, 물리 Android·iOS 검수, 개인정보 법률 적합성 최종 승인.

**다음 사용자 입력이 단순히 '진행'이어도 새 프로젝트 생성 금지는 유지한다.** 프로젝트 생성은 명시적으로 요청받았을 때에만 진행한다. 프로젝트 생성 권한의 존재를 생성 승인으로 간주하지 않는다.
