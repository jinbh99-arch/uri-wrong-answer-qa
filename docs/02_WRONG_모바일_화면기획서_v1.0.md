# 02 WRONG 모바일 화면기획서 v1.0
> 문서 전용 격리 QA / 기준 dev `8bb3055d6af6e2537c32b89e3b054598c4bc7e51` / 2026-11-15 KST. **실제 제품 캡처가 아닌 390px 예정 도식**. 제품·운영 배포 없음.

## 1. 왜 필요한가
- **문제:** 종이 오답을 사진·텍스트로 기록한 뒤 아이가 다시 풀고, 부모가 관찰하고 재확인하는 과정이 끊기기 쉽다.
- **사용자:** 부모(입력·수정·관찰·재확인 관리), 아이(허용된 문제 재풀이·설명). 아이 화면에 부모 메모·사진 편집 흔적·OCR 초안이 남아서는 안 된다.
- **가치:** 한 오답의 등록→재풀이→부모 관찰→재확인 흐름을 연결하되 사진 원본·오답 원장을 잃지 않고, 복원·가족 인증의 미검증을 완료처럼 표시하지 않는다.

## 2. 모바일 흐름
`01 첫 진입(부모)` → `02 사진/문제 입력` → `03 OCR 확인·수정` → `04 오답 저장/목록` → `05 아이 재풀이` → `06 아이 설명` → `07 부모 관찰` → `08 재확인 예약/결과` → `09 백업·복원·삭제(보호 게이트)`.
분기: 사진/OCR 실패→수동 문제 입력(02); 저장 실패→입력 유지·재시도(03/04); 아이 모드 종료→부모 영역 복귀(07, **보기 모드≠가족 인증**); 복원/삭제→미검증 차단(09).

## 4. 현재 구현과 증거의 경계
- **기존 가상 캡처 10장(과거 검증):** [fixed 갤러리](../qa79-fixed-320px/README.md). 최신 dev의 모든 화면을 실증한다는 의미는 아님.
- **기존 로컬 시연 안내:** [부모·아이 클릭형 동선](../wrong-local-parent-journey-v1/README.md). 가상 자료만 사용.
- **W7 원자성:** [PR79](https://github.com/jinbh99-arch/uri-wrong-answer-qa/pull/79) 신규 Chromium 320px 일부 PASS; [PR80](https://github.com/jinbh99-arch/uri-wrong-answer-qa/pull/80) WebKit 사진 초기 저장 단계 미검증, Draft.
- **실제 체험 URL:** Netlify 기존 환경의 외부 인증·최신 dev 반영·실가족 분리 실증이 없어 **제공 불가**. 위 GitHub 문서 링크는 비배포 자료 열람이며 서비스 접속 주소가 아님.
- **아직 증명하지 못한 것:** 실제 OCR/실사진, 실기기 200%·키보드, 부모 메모 모드왕복, 가족 A/B 인증·HTTP403, 원본 복원·삭제 안전, 실제 인터넷 접근 통제. 보기 모드만으로 개인정보 접근권한을 부여하지 않는다.

## 5. 우선순위
- **v1 필수:** 사진/수동 입력, OCR 초안 확인, 무손실 저장, 아이 재풀이·설명, 부모 관찰과 재확인 상태 분리, 아이 DOM 개인정보 차단, 미저장 메모 보존, 320px 키보드/확대 접근성, 실제 가족 접근 인증·격리 증거.
- **후속 또는 별도 승인:** 안전한 암호화 백업·원자 복원, 가족별 삭제, 인증된 비운영 인터넷 시연. `safeToRestore:false`를 유지하며 검증 전 기능 출시 금지.
